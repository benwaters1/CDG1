Outlook add-in

House calendar

A panel beside a guest's email in Outlook — on a computer, in a browser, on a phone — with the whole of that guest in it: what they have booked, what to watch for, every email with them across the house's inboxes, and, for you, what they owe. A reply drafted from all of it and today's real prices. And a check, before a reply goes, that its prices and dates are still true. Everybody signs in with their own Microsoft 365 account; colleagues see everything but money.

Putting it in everybody's Outlook

Once, for everybody, from Microsoft 365 admin (the way to do it):

  1. Microsoft 365 admin centre → Settings → Integrated apps → Upload custom apps.
  2. App type: Office Add-in. Choose "Provide link to manifest file" and paste {% if manifest_url %}{{ manifest_url }}{% else %}the manifest address, once ADDIN_BASE_URL is set (above){% endif %}. Validate.
  3. Assign it to everybody who answers guests (or the whole organisation), and choose Fixed so nobody has to switch it on. Deploy.
  4. It reaches Outlook within a few hours (Microsoft says up to 24). It then appears as Gudanes on every message, on desktops, the web and phones.

When this page shows a new version number, open the add-in in Integrated apps and choose "Update" so Microsoft fetches the new manifest; Outlook keeps the old one until then.

One person, to try it first: Outlook on the web → Settings → Mail → Customise actions → Get add-ins → My add-ins → Add a custom add-in → From URL, and paste the address above.

Setting it up (Entra admin centre, signed in as an administrator):

  1. App registrations → New registration. Name Gudanes Outlook add-in. Accounts in this organisational directory only. Register.
  2. Authentication → Add a platform → Single-page application, redirect URI {% if addin_origin %}brk-multihub://{{ addin_origin|replace('https://', '')|replace('http://', '') }}{% else %}brk-multihub:// followed by the add-in's address, once ADDIN_BASE_URL is set (above){% endif %}. Save.
  3. Expose an API → Application ID URI: accept api://<the client id>. Add a scope: access_as_user, who can consent "Admins and users", display name "Use the Gudanes add-in as you". Save.
  4. API permissions → Add a permission → My APIs → this app → access_as_user. Then Grant admin consent for the organisation, so nobody is asked.
  5. Copy the Application (client) ID into Railway as ADDIN_CLIENT_ID and redeploy. The tenant is the one the mail reader already uses.

No secret is needed for this one: the add-in signs in as the person, through Outlook. The add-in keeps its own address when the site and the staff side move to the house's domain, so this redirect URI does not change with them.

Checks on Send

Every email going outside the house is checked when Send is pressed: its prices and dates against the booking system. A wrong one is stopped with the right one named, and the person chooses whether to send it anyway. The check has three seconds. When it cannot run, the person is told and decides, and the Outlook is listed here until its next email is checked.

Settings

Answers to questions guests ask that are not on the website: parking, pets, the Wi-Fi, the road in winter. Every draft is given this, alongside the rooms, the table, the ateliers and the terms the site already holds.

What is sent where

The panel reads the house's mailboxes through Microsoft 365 when it is opened; emails are held in memory for a few minutes and never copied into this app. A draft sends Anthropic the guest's bookings, the emails in the conversation and the ones before it, the staff notes, and the house's own facts — not their telephone, not anything about their health, and, for anybody who asked us to stop using their details, nothing but the email being answered. The privacy notice says so.
